# 物理设计

## 链接

#### 链接属性

1. 外部链接意味着，一个名字所指代的实体可以通过其他翻译单元中的声明被引用。

```cpp
// a.cpp
int value = 42;
```

```cpp
// b.cpp
extern int value;

int main() {
    return value;
}
```

2. 内部链接意味着，同一个翻译单元内的不同声明可以指代同一个实体，但这种身份不会通过该名字延伸到其他翻译单元。

匿名 namespace 用来平替 static 可能更好用

```cpp
namespace {
int counter = 0;
}
```

3. 无链接意味着，这个名字不具有跨声明建立同一实体身份的链接属性。

```cpp
void f() {
    int x = 1;

}

void g() {
    int x = 1;
}
```

#### 绑定

我们将物理链接的过程成为绑定, 与逻辑链接区分

1. 内部绑定: 编译翻译单元的使用时就已确定这个名字的定义, 不需要跨翻译单元工作
2. 外部绑定: 需要跨翻译单元, 不能重复定义
3. 双重绑定: 需要跨翻译单元, 但可以重复定义, 例如 `inline` 修饰的函数和变量

不光是 `inline` 修饰的函数和变量, 类类型定义、函数模板定义、类模板定义 都可以多个翻译单元有相同定义而不违反 ODR

这一设计主要都是为了能让多个要用到 这个类 (的成员)、模板实例化 的地方都能够得到足够的信息——模板实例化是在编译阶段进行的, 所以需要完整的实现, 因为链接器是比较独立于 C++ 语言之外的

需要注意的是, 模板函数的显式特化并不是模板函数, 而是普通的函数, 所以也具有外部绑定

### 升级

考虑两个组件 A B, 我们可能会需要他们互相转换:

最坏的情况是头文件间物理循环依赖, 无法编译 (总有一个类是 incomplete type): 

```cpp
// A.h
#pragma once 
#include "B.h"
struct B;
struct A {
  A(const B& b) {
    // ...
  }
  // ...
};
```

```cpp
// B.h
#pragma once
#include "A.h"
struct A;
struct B {
  B(const A& a) {
    // ...
  }
  // ...
};
```

考虑把实现挪到 cc 中:

```cpp
// A.h
#pragma once 
struct B;
struct A {
  A(const B& b);
  // ...
};
```

```cpp
// B.h
#pragma once
struct A;
struct B {
  B(const A& a);
  // ...
};
```

A.cc 依赖 A.h B.h; B.cc 依赖 A.h B.h

名称的循环依赖

- 仍然有不必要的依赖: 用户可能只用 A, 不需要 B
- 修改任意头文件都会导致两个 cc 都重新编译

这不够好, 我们可以:

- 决定 A 和 B 哪个更基础, 然后重新组织为单向的依赖关系
- 用上层 utility 类提供 A 和 B 的非成员相互转换:

```cpp
// C.h
#pragma once
#include "A.h"
#include "B.h"

struct A;
struct B;
struct C {
    static A toA(B);
    static B toB(A);
};
```

### 不透明指针

低层级的组件 A 不应该直接调用高层级 B 组件的函数, 而是通过向更高层级 C 返回 B 的不透明指针 (Holds 关系), 让更高层级来负责调用

```cpp
// A.h
struct B;

struct A {
  B* b_;
  A(B b): b_(b) {}
  B* getB() { return this.b_; }
  // ...
};
```

如果⼀个指针所指向的类型的定义不包含在当前的编译单元中, 这个指针就被称为是不透明的

### 哑数据

有些时候我们可以比不透明指针更进一步, 不止是指针

比如类 A 有一个类 B 数组, 还依赖于一个类 C, 会对 B 数组的一些元素进行挑选、记录或传回等不需要 B 内部实现的操作

C 可以直接不知道 B 的名字, 只需要把要处理的 B 元素的下标发送给 C; 这里的下标就是哑数据

### 冗余

类似多线程的通过复制避免同步

A 和 B 当前在实现上有相同的部分 不代表 一定要抽出来合并

### 回调

一种控制反转手段

允许在低层级执行高层级的自定义操作
